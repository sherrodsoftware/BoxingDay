# Changelog

## Unreleased

- **Enhanced Security.** Boxing Day now uses Apple's Enhanced Security protections: a hardened memory allocator, read-only dynamic linker state, and runtime restrictions on the libraries it loads and the messages it receives from other processes. On Macs with an M5 chip or later, hardware memory tagging runs in soft mode, which records memory errors as simulated crash reports instead of quitting. Pointer authentication (an `arm64e` build) is left off for now because the Sparkle framework doesn't ship that architecture. The decisions are recorded in docs/xcode-security-settings.md.
- **Google Chrome shows as signed.** Some disk images, including Google Chrome's, ship apps whose files carry Finder metadata. The code signature doesn't cover it, but Boxing Day's strict signature check rejected it, so Chrome showed "Unsigned or signature invalid" even though it's properly signed. Boxing Day now removes that metadata from its own copy of the app (never the original) before checking, so the check passes, the staged copy is verified again before packaging, and the installed app no longer carries the metadata.
- **Menus update on their own.** The File, Package, and Check for Updates menu items are now built as small views that follow Boxing Day's state, so they enable and disable as soon as a build starts, finishes, or the upload sheet opens. Before, the window handed the menu bar a new set of actions each time it redrew, including on every keystroke in Identifier or Version, which refreshed the menus even when nothing had changed.
- **Less redrawing in the main window.** Each part of the window — the drop zone, the selected app or package, the package details, and the status card — now redraws only when what it shows changes. Typing in Identifier or Version redraws just the package details, instead of the whole window including the app icon and status card.
- **Settings forgets the client secret when it closes.** Settings reads the Jamf Pro API client secret from the Keychain each time it opens and clears it from memory when it closes, as the upload sheet already did, instead of keeping it for as long as Boxing Day runs. Each part of Settings now redraws only when what it shows changes, so typing in a connection field no longer redraws the category picker or status. Settings keeps its state in a separate model, with tests that use in-memory settings for when Save is available, what Save stores, what Forget Connection clears, and which default category is chosen, plus end-to-end tests of Settings and the upload sheet against a fake Jamf Pro server.
- **Quicker startup cleanup.** At launch, Boxing Day looks for temporary files left behind by an earlier run that quit unexpectedly. It used to list the whole temporary folder twice, reading details for every item in it, even though only Boxing Day's own items matter; profiling showed this was its largest single cost at launch, about 8 ms with a few thousand items. It now lists the folder once, by name, and looks only at its own items, which takes about half as long and no longer grows with other apps' files.
- **Jamf Pro URL placeholder.** With no server entered, Settings showed the example URL as a blue link instead of grey placeholder text like the other fields.
- **About Boxing Day.** The About panel shows © Sherrod Software and a link to www.sherrodsoftware.com below the version, like Version Report.
- **Less redrawing while uploading.** The Upload to Jamf Pro sheet used to redraw in full five times a second for the whole upload, to move the progress bar. Now only the progress bar and percentage redraw, and only when the percentage changes, so a large package sends about 100 updates in all. Each part of the sheet — the record fields, categories, connection, activity, and result — also redraws only when what it shows changes, so typing in a field no longer redraws the rest of the sheet. Each step in Jamf Activity keeps its own state, so a new step redraws only itself and the step it finished. The sheet keeps its state in a separate model, with tests for when Upload is available, blocking a filename that's already in use in Jamf Pro, and the messages shown after a cancelled or failed upload.
- **Release script.** `scripts/release.sh` runs the tests, archives, exports with Developer ID, checks the app's and Sparkle's signatures, builds and notarizes the installer package, and prints the Sparkle appcast values.

## Boxing Day 2026.11.06

- **The window opens on the second launch.** When Boxing Day asked whether to check for updates automatically, its main window no longer stays closed until you click the Dock icon.
- **Boxing Day Help.** Help > Boxing Day Help (⌘?) opens the Boxing Day page on GitHub.

## Boxing Day 2026.11.02

- **Automatic updates.** Boxing Day checks for updates with Sparkle. Choose Boxing Day > Check for Updates… to check at any time.
- **Cancel long-running work.** Cancel a package build or a Jamf Pro upload while it's running. A partially written package is removed. A cancelled upload says whether a package record was already created in Jamf Pro, and blocks retrying with a filename that's already in use.
- **Menus and keyboard.** File > Open… (⌘O) and a Package menu with Build Package… (⌘B), Upload to Jamf Pro… (⌘U) and Reveal in Finder (⇧⌘R). Return triggers the primary button and Esc cancels. Open and save panels attach to the window.
- **Accessibility.** VoiceOver describes the drop zone, offers a Choose File action, and announces build and upload progress.
- **Other improvements.** A Copy Error button beside Save Error as Text…; a single window that quits when closed; cards that follow Dark Mode and Increase Contrast; an upload sheet and Settings window that grow with larger text; and choosing a category for one upload no longer changes the default in Settings.
- **Fixes.** A failed disk image could have files deleted while still mounted; a command-line tool producing a lot of error output could hang; the duplicate-package check missed filenames with leading or trailing spaces; and the window froze while checking a large app's code signature.
